# addon-renovate — automated dependency update PRs

Platform add-on: a [Renovate](https://docs.renovatebot.com/) bot that scans
every repository in the `devhub` organisation and opens pull requests for
outdated dependencies — the self-hosted equivalent of Dependabot, talking to
Forgejo through its Gitea-compatible API.

**This includes the platform repository.** `./devhub gitops-repo` publishes the
platform as `devhub/<repo>` in this same Forgejo, with a `renovate.json` whose
custom managers know where the Helm chart pins live (the deploy scripts and
`k8s/argocd/platform-appset.yaml`). That file needs something to run Renovate,
and `autodiscover: devhub/*` below is that something — so this add-on is what
keeps the platform's own charts moving after the handover, not just the
applications'. See `k8s/docs/ADDONS.md` for the two caveats (a repository in a
different organisation needs the filter widened, and a bootstrap-component bump
still needs `deploy.sh <component>` run).

## How it deploys

This directory is published to `devhub-templates/addon-renovate` by
`deploy.sh <env> portal-templates`. Enabling the add-on in the portal copies it
to `devhub/addon-renovate`, and from there the ordinary conventions run it:

- `forgejo-appset` sees a `devhub`-org repo with raw manifests under `k8s/`
  and deploys them to every registered workload cluster
- the namespace `devhub-addon-renovate` gets its quota, LimitRange and
  NetworkPolicies generated by Kyverno, like any app namespace
- the image comes from `ghcr.io`, which the registry allow-list permits

No image build, no CI: the CronJob runs the stock upstream Renovate image on a
daily schedule and exits. The only state is in Forgejo (branches and PRs) and
the dependency dashboard issue Renovate maintains per repository.

## What it needs from a human

One secret: a Forgejo token in Vault at `secret/apps/addon-renovate`
(key `token`). The portal opens SETUP.md as an issue on the enabled repository
with the exact steps.

## Configuration

`k8s/renovate-config.yaml` holds the Renovate config: which repos to scan
(`autodiscoverFilter`), PR rate limits, onboarding behaviour. The schedule
lives on the CronJob in `k8s/renovate-cronjob.yaml`. Edit the enabled
repository (`devhub/addon-renovate`) — ArgoCD reconciles the change; this
template only seeds it.

Renovate autodiscovers `devhub/*`, which includes `devhub/addon-renovate`
itself — once onboarded, it keeps its own image pin current too.

## Known limits

- On the `local` environment the bot cannot reach `git.localhost` from inside
  the cluster (glibc resolves `*.localhost` to loopback before DNS). This
  add-on is for environments with a real domain.
- Changelogs for github.com-hosted dependencies are fetched anonymously and
  may be rate-limited; set `GITHUB_COM_TOKEN` on the CronJob if that matters.
